01 — The three

One language, three rules.

The port came first. The other two fork it and change one thing: what each is allowed to do. Each has its own page, and every number on those pages links to the file it came from.

01 · the port

The F# port

Translate it, byte for byte.

The ruleDo the same work per request as Basecamp's Rust port, and render every screen byte-identical to it.

Translated crate by crate from the Rust port by phased agent workflows: its own front server, SQLite layer, HTML writer and HTML5 parser, all in F#. It matched every parity screen byte for byte, then ran 1.24-1.33x the Rust port it was translated from. Basecamp's Rust has since added full-page caching, so on today's harness the port does 0.71× Rust on the room page.

02 · onCrack

onCrack

Same pixels, no speed limit.

The ruleDo any work you like, as long as every screen stays pixel-identical to Rails and no one ever sees a stale page or someone else's.

Versioned page caches that re-check the session and room membership on every hit, group commit for concurrent posts, cache hits answered by the front server, gathered Cable writes, and a Cable log that keeps every reader. The fastest of the six in every workload, and in Basecamp's 1,000-client Cable test it cut 0 clients where Rust cut 902-959. It pays in memory, and it is the largest of the three.

03 · theDotNetWay

theDotNetWay

Let the framework do it.

The ruleWrite it the way a .NET team would: the standard piece for every layer, hand-written code only where Rails parity demands it.

Forked from the port and rebuilt one layer at a time behind the pixel gate: Kestrel and ASP.NET Core middleware for the front server, EF Core with Dapper on the hot reads, Falco.Markup views, AngleSharp for HTML, WebSockets with Channel<T> for Cable, HybridCache for pages. The smallest of the three and smaller than Rust; slower than Rust, C and onCrack.

04 — The method

A rewrite counts only if it can't be told apart.

Same loop each time. The rule changes; the gates don't.

Reference

Pin the original

Rails and Basecamp's Rust port, pinned as submodules, with the Rust port's parity harness and golden vectors.

Rule

Pick one constraint

Same work as Rust; any work at all; the framework's way. Everything else stays: the database, the cookies, the pages.

Claude Code

Build in phases

Agent workflows design each phase, build it unit by unit, and hand it to an independent, adversarial verifier.

Gates

Prove it's the same

Screenshot, accessibility-tree and DOM parity on every seed, a cookie round trip and a database differential with Rails, then Basecamp's harness.

Chris Kluis set each rule, made the calls and decided what shipped. Claude Code did the translating, building, testing and measuring.
