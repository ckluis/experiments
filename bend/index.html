Bend is a functional language that compiles to C and runs on CPU or GPU. An AI app builder used it to write a backend framework, a CMS on top of it, and a whole desktop shell, each shipped with passing tests and a ledger of evidence. Claude Code was then asked the same question every time: is any of this actually true?

02 — The language

Why Bend is a hard place to build.

Bend is young, strict about purity, and changes fast. Those are the conditions that make an AI builder's claims worth checking.

Compiles to C

One C file serves as both the CPU program and the GPU kernel. clang builds a native binary; the same source can emit JS.

Affine by default

A value is used once unless marked reusable. Matches only work on parameters, there are no forward references, and no mutual recursion.

Strict, so helpers bite

A pick(cond, a, b) helper evaluates both sides. That one line made the bochtCMS parser quadratic.

Moving fast

The builder logged breaking changes in 2.0.27, 2.0.29, 2.0.32 and 2.0.34, four in 12 days. Bend 2.0.35 (3 Oct) needed one line, in bocht; the CMS and the shell built unchanged.

03 — The method

Nothing counts until it's re-derived.

Same loop, three times. The builder writes and tests under its own discipline; Claude Code starts from the bundle, not the builder's word.

Builder

Write and ledger

Probes that print one PASS line, results bound to a binary's hash, a verifier that audits the ledger.

Claude Code

Reproduce

Rebuild from source on a different OS and CPU. Re-run every claim. Check every hash.

Claude Code

Attack and look

Adversarial requests, realistic sizes, timing sweeps, and screenshots of the real window.

Claude Code

Fix and prove

Smallest fix, a probe that fails before and passes after, and a differential against the original.

A person sits at the end of each loop: Chris Kluis asked for every evaluation, rejected a builder's fix, picked the designs, and decided what ships.

04 — What it found

Green suites, real bugs.

Across all three, the builder's tests passed every time. They were checking the wrong thing: tiny payloads, internal state, the builder's own expectations.

01

Size is a test input.

All 43 CMS checks used tiny payloads. The bug only showed at realistic post sizes, and grew with the square of them.

02

State isn't the screen.

shellOS's suites proved the palette and help opened. The window never showed them. Only screenshots caught it.

03

A fix needs a differential.

The builder's "O(n²) fixed" was no faster and changed seven behaviors, one of which turned a read into a delete. Its suite still passed.

04

Manifests prove provenance.

Binding results to a binary's hash proves which build produced a log, not that the log tested the right things.

05

Evidence travels.

Every hash in every bundle matched. The discipline made each audit fast; it just couldn't audit itself.

06

Someone has to decide.

One AI wrote it, another checked it, and the person in the loop decided which one to believe.

Three builds. Three audits. Every claim re-derived from disk.
